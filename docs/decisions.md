# Technical decisions and tested environment

Audit date: 2026-10-27 (Asia/Ho_Chi_Minh). This stabilizes the existing layered architecture rather than replacing it.

## Environment diagnosis

The initial resolver failures came from an execution sandbox that prohibited socket creation; apparent DNS failures were not evidence of a host DNS or PyPI outage. Ordinary Python socket attempts were denied. An available Nix shell execution environment could reach PyPI with valid TLS, resolve/download wheels, and run loopback HTTP. `curl -s --max-time 10 -I https://pypi.org/simple/` returned HTTP/2 200. No system DNS, firewall, proxy, or NixOS configuration was changed, and no TLS verification was disabled. Python reported no configured proxy settings; DNS returned 24 addresses for pypi.org and a TLS-verified urllib HTTPS HEAD request also returned 200. No proxy workaround was needed.

Existing uv/pip caches did not initially provide a complete ML environment. Dependencies were actually acquired into isolated uv environments; the tested session used `/tmp/uv-cache`. The project shell normally selects `.local/uv-cache`. Cache location is operational and not embedded in the lockfile.

Host: NixOS 26.05, Linux x86_64, CPython 3.11.16, uv 0.11.21. Manylinux NumPy/Torch/CTranslate2 wheels require `libstdc++.so.6`; `shell.nix` supplies it through LD_LIBRARY_PATH. Native inference and local HTTP serving worked in that shell. Python 3.12+ and other architectures were not tested.

`uv.lock` is generated by uv, not hand-written. Torch and TorchVision resolve together against the explicit CPU index on Linux; actual detection and embedding execution confirms their binary/operator compatibility. faster-whisper/CTranslate2 ran real CPU INT8 transcription. The clean pip wheel test additionally resolved Pydantic 2.14.1 and passed lightweight operations; that does not replace the locked runtime test.

Six separate environments verified `base`, `ui`, `detection`, `speech`, `retrieval`, and `all` extras. Base has no Gradio or Torch; UI and speech do not require Torch. Model modules defer optional native imports until load. Package metadata uses bounded compatibility ranges, while the lockfile supplies reproducibility for uv. Hatchling is pinned to the actual tested build version.

## API checks

The installed Gradio 5 APIs were checked by construction, localhost launch, and gradio-client upload/callback/download tests. Selected TorchVision weight enums and official transforms were checked by actual inference. Model constructors disable implicit backbone weights. The faster-whisper segment generator is consumed within prediction, covered by a deterministic timing test and real transcription.

Reference documentation: [Gradio Blocks](https://www.gradio.app/docs/gradio/blocks), [TorchVision models](https://docs.pytorch.org/vision/stable/models.html), [PyTorch CPU installation](https://pytorch.org/get-started/locally/), [faster-whisper](https://github.com/SYSTRAN/faster-whisper), [CTranslate2 installation](https://opennmt.net/CTranslate2/installation.html), [Pydantic v2](https://docs.pydantic.dev/latest/), and [Typer](https://typer.tiangolo.com/).

No Git clean/dirty assessment is possible: the visible `.git` is an empty read-only environment mount, as confirmed by the later publication audit. It does not establish whether host-side history exists. No commits, pushes, package publishing, releases, or public deployment were performed.
